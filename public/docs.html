TrainOS のトップへ

改造・独自アプリ docs

フォルダ構成

TrainOS/            選んだフォルダ（または Drive の TrainOS/）
├─ sys/
│  ├─ settings.json   設定（bootLoader, fileTypeHandlers ...）
│  ├─ boot_loader/    起動画面。複数置ける
│  ├─ components/     OS の挙動を差し替える JS
│  └─ apps/           アプリ。置くだけで使える
└─ usr/               desktop/ documents/ など

アプリを作る

単体HTML型: sys/apps/hello.html を置くだけ。

<pre id="out">読み込み中…</pre>
<script>
TrainOS.fs.readText('/usr/documents/memo.txt')
  .then(t => out.textContent = t)
  .catch(e => out.textContent = e.message);
</script>

フォルダ型（推奨）: sys/apps/mytool/ に index.html と app.json など。CSS・JS・画像を分けられる。

{
  "id": "mytool", "name": "My Tool",
  "entry": "index.html",
  "extensions": ["txt"],
  "permissions": ["fs.read", "fs.write"]
}

SDK（アプリ内の window.TrainOS）:

TrainOS.fs.readFile(p) / readText(p) / writeFile(p, data)
TrainOS.fs.list(p) / tree(p) / mkdir(p) / remove(p)
TrainOS.app.setTitle(t) / close() / openFile(p)
TrainOS.app.onOpen(fn)   // 他から開かれたとき fn(path)
TrainOS.fs.move(from, to)
TrainOS.sys.getSettings() / setSettings(patch) / flush()   // system.settings が必要
TrainOS.icon(name)       // Font Awesome の SVG 文字列
  • 権限: fs.read fs.write app.launch（openFile 用）、system.settings（設定の読み書き）。app.json で指定すると既定値を置き換える。
  • 相対パスの script / link / img はアプリフォルダ内だけ解決される。実行時の fetch や import() では同フォルダを読めないので TrainOS.fs を使う。
  • alert / prompt / confirm は使えない。

起動画面（ブートローダー）

sys/boot_loader/名前.js を置く。example.js（プログレスバー）と redver.js（赤いスピナー）が入っている。

TrainOSBoot.register({
  name: 'mine',
  start(el) { el.textContent = 'booting…'; },   // el = 起動画面の要素
  progress({ value, label }) { /* 0-100 と表示文字 */ },
  done() {}                                      // 省略可
});
  • 切り替え: settings.json の bootLoader を名前にする。設定画面やターミナルからは TrainOSBoot.use(kernel, '名前')。
  • ログイン前は Drive を読めないため、選択中のローダーはブラウザにキャッシュされ、次回起動時に使われる。ファイルを編集したら、一度ログインして起動すると反映される。
  • 初回や未設定のときは内蔵のシンプルな画面になる。

セーフモード

URL に ?mode=safe を付けると、sys/components/ のコードとキャッシュ済みブートローダーを無視して、内蔵 UI で起動する。壊したコードの修復用。

保存先

ローカルフォルダは Chrome / Edge（デスクトップ）のみ。選んだフォルダが TrainOS のルートになる。ブラウザを閉じるとフォルダの許可が切れることがあるので、index.html から起動して許可し直す。

Google Drive 版のセットアップ

  1. Firebase でプロジェクトを作り、Authentication で Google ログインを有効にする。配信元のドメインを承認済みドメインに追加する。
  2. 同じプロジェクトで Google Drive API を有効にする。
  3. firebase-config.js に Web アプリの設定値を入れる。
  4. 起動時に「Google でログイン」を押す。Drive のフルアクセス権限を求められる（確認前のアプリは警告が出る。自分用ならテストユーザーに自分を追加する）。

Drive の TrainOS/ フォルダがルートになる。書き込みはまとめて送られるので、タスクバーの保存ボタンで今すぐ送れる。
