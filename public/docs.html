TrainOS のトップへ

改造・独自アプリ docs

フォルダ構成

TrainOS/            選んだフォルダ（または Drive の TrainOS/）
├─ sys/
│  ├─ settings.json   設定
│  ├─ desktops/       デスクトップ環境（全部の設定のまとめ。JSON）
│  ├─ wm/             ウィンドウマネージャー（JS）
│  ├─ window_themes/  ウィンドウテーマ（CSS）
│  ├─ shell_themes/   シェルテーマ（CSS）
│  ├─ panels/         パネル = ドック・タスクバー（JSON）
│  ├─ cursors/        マウスカーソル（JSON）
│  ├─ animations/     アニメーション（CSS）
│  ├─ wallpapers/     壁紙（画像、動く SVG、動く HTML）
│  ├─ fonts/          フォント
│  ├─ keymaps/        キー割り当て（JSON）
│  ├─ iconsets/       アイコンの差し替え（JSON）
│  ├─ boot_loader/    起動画面（JS）
│  ├─ components/     起動時に動く JS。ファイルごとにオンオフ
│  ├─ sounds/         効果音のテーマ（JSON）と音声ファイル
│  ├─ startup/        起動時に開くアプリ（JSON）
│  ├─ permissions.json  アプリごとの許可の記録（自動。設定画面で変えられる）
│  └─ apps/           アプリ。置くだけで使える
└─ usr/               desktop/ documents/ など

アプリを作る

単体HTML型: sys/apps/hello.html を置くだけ。

<pre id="out">読み込み中…</pre>
<script>
TrainOS.fs.readText('/usr/documents/memo.txt')
  .then(t => out.textContent = t)
  .catch(e => out.textContent = e.message);
</script>

フォルダ型（推奨）: sys/apps/mytool/ に index.html と app.json など。CSS・JS・画像を分けられる。

{
  "id": "mytool", "name": "My Tool",
  "entry": "index.html",
  "extensions": ["txt"],
  "permissions": ["fs.read", "fs.write"]
}

SDK（アプリ内の window.TrainOS）:

TrainOS.fs.readFile(p) / readText(p) / writeFile(p, data)
TrainOS.fs.list(p) / tree(p) / mkdir(p) / remove(p)
TrainOS.app.setTitle(t) / close() / openFile(p)
TrainOS.app.onOpen(fn)   // 他から開かれたとき fn(path)
TrainOS.fs.move(from, to)
TrainOS.fs.copy(from, to)                // フォルダは中身ごと。コピー先がすでにあるとエラー（fs.write）
TrainOS.fs.download(name, data)          // ブラウザのダウンロードとして保存（Blob か文字列。fs.read）
TrainOS.sys.getSettings() / setSettings(patch) / flush()   // system.settings が必要
TrainOS.sys.saveKeymap(name, map)                          // sys/keymaps/名前.json に保存して切り替える（system.settings）
TrainOS.ui.alert(message, opts) / confirm(message, opts) / prompt(message, opts) / choose(message, buttons, opts)   // ダイアログ（権限は不要）
TrainOS.sound.play(name) // 効果音のテーマにある名前を鳴らす
TrainOS.sys.getPermissions() / setAppPermission(id, perm, allowed) / resetAppPermissions(id)   // アプリの権限（system.settings）
TrainOS.sys.addStartup(id) / removeStartup(name)           // 起動時に開くアプリ（system.settings）
TrainOS.icon(name)       // Font Awesome の SVG 文字列
  • 権限: fs.read fs.write app.launch（openFile 用）、system.settings（設定の読み書き）。app.json で指定すると既定値を置き換える。
  • 相対パスの script / link / img はアプリフォルダ内だけ解決される。実行時の fetch や import() では同フォルダを読めないので TrainOS.fs を使う。
  • alert / prompt / confirm のブラウザ標準のものは使えない。代わりに TrainOS.ui を使う（下の「ダイアログ」）。window.alert(…) だけは、同じ見た目のダイアログに置き換わっている（待たずに続く）。

ダイアログ（TrainOS.ui）

await TrainOS.ui.alert('保存しました')                              // 閉じたら続く
const ok = await TrainOS.ui.confirm('削除しますか？', { okLabel: '削除', danger: true })   // true / false
const name = await TrainOS.ui.prompt('名前は？', { value: 'memo', placeholder: '…' })      // 文字列 / キャンセルは null
const v = await TrainOS.ui.choose('どれにする？', ['A', { label: 'B（既定）', value: 2 }]) // 選んだ値 / Esc は null
  • オプション: title、okLabel、cancelLabel、danger（confirm。赤くして、最初はキャンセルを選ぶ）、multiline（prompt）。choose の値は文字列・数値・真偽値。選択肢は 8 個まで。
  • そのアプリのウィンドウの中だけを覆うので、ほかのウィンドウは使える。出ている間、アプリの中は操作できない。ウィンドウを閉じるとキャンセル扱い。
  • 先頭に「アプリ名 からのメッセージ」が必ず出る（アプリが OS のふりをできない）。題名は 100 文字、本文は 4000 文字まで。同時には 1 つずつ、順番に出る。
  • Enter（prompt の入力欄）で決定、Esc でキャンセル、Tab で移動。

権限の確認画面

  • 標準アプリ（インストールしたときのまま、app.json に手を加えていないもの）は、確認なしで使える。
  • それ以外のアプリ（自分で置いたもの、app.json を書き換えた標準アプリ、単体HTML型）は、初めて起動するときに、求めている権限の一覧が出る。許可するものにチェックを入れて「許可して起動」。チェックを外した権限は、アプリから使えない。「起動しない」か Esc なら、何も記録せず、起動しない。
  • 「OS の設定を変える」（system.settings）は、最初はチェックが外れている。fs.write と合わせて、赤く出る。
  • 許可と断ったことは sys/permissions.json に残り、次からは聞かない。app.json が新しい権限を求めたときだけ、その分を聞き直す。
  • あとから変えるには、設定画面の「アプリの権限」。変更は、開いているアプリにもすぐ効く。「記録を消す」と、次の起動でまた確認する。
  • 許可は、アプリの id に結び付く。許可したあとにアプリの中身を差し替えても、app.json の要求が同じなら、聞き直さない。信用できないファイルは置かない。system.settings を許したアプリは、自分や他のアプリの権限も変えられる。

components の API

sys/components/名前.js は、起動時に名前順で実行される。2つの変数が使える。kernel（OS の機能）と component（この component 用の、イベントとフック。失敗すると、名前を付けて警告が出る）。1つ壊れても、ほかは動く。ファイルごとに設定画面でオフにできる（次の起動から）。壊したときはセーフモード（?mode=safe）。

component.on('ready', () => console.log('デスクトップが開いた'));
component.hook('fs.delete', (ctx) => { if (ctx.path.startsWith('/usr/documents/keep/')) return false; });
component.hook('openFile', (ctx) => { if (ctx.path.endsWith('.log')) ctx.appId = 'notepad'; });

イベント（知らせるだけ。戻り値は見ない）

component.on(名前, fn) / once。kernel.on / once / off も同じ（on の戻り値は解除する関数）。

  • ready: デスクトップが開いた（起動画面が消えたあと）。
  • fs: (パス, 種類)。種類は write mkdir delete。
  • settings: 設定が変わった。apps: アプリの起動・終了・一覧の更新。
  • app:launch / app:close / app:focus: ({ instance })。instance.appId、title、perms など。
  • file:open: ({ path, appId })。ファイルを関連付けで開くとき。

フック（操作の前に呼ばれる。止める・書き換える）

component.hook(名前, fn)（kernel.hook も同じ。戻り値は解除する関数）。fn(ctx) は、false を返すと操作を中止する。それ以外（戻り値なし、例外、5 秒を超える待ち）は、そのまま続ける。async でもよい。

  • launch: { appId, openPath }。書き換えると、別のアプリ・別のファイルで起動する。中止すると何も起きない。
  • openFile: { path, appId }。appId を書き換えると、開くアプリを変えられる（関連付けのない拡張子にもできる）。
  • fs.write: { path, size }。fs.delete: { path }。中止すると、書き込み・削除はエラーになる（アプリからも、OS からも）。
  • syscall: { appId, method, args }。アプリからのシステムコールを、権限の確認のあとに止められる。

そのほか components から使えるもの

  • kernel.ui.alert / confirm / prompt / choose: 画面の真ん中のダイアログ（使い方は TrainOS.ui と同じ。第 2 引数に sound: 'error' など）。
  • kernel.sound.play(名前): 効果音。kernel.apiVersion（いまは 1）。
  • kernel.settings / kernel.setSettings(patch) / kernel.readFile / writeFile / find / apps.launch / openFile など。
  • フックを付ける component が、止めてはいけないものまで止めると、OS が使いにくくなる。そのときは、セーフモードで起動して、その component を消すかオフにする。

起動画面（ブートローダー）

sys/boot_loader/名前.js を置く。example.js（プログレスバー）と redver.js（赤いスピナー）が入っている。

TrainOSBoot.register({
  name: 'mine',
  start(el) { el.textContent = 'booting…'; },   // el = 起動画面の要素
  progress({ value, label }) { /* 0-100 と表示文字 */ },
  done() {}                                      // 省略可
});
  • 切り替え: settings.json の bootLoader を名前にする。設定画面やターミナルからは TrainOSBoot.use(kernel, '名前')。
  • ログイン前は Drive を読めないため、選択中のローダーはブラウザにキャッシュされ、次回起動時に使われる。ファイルを編集したら、一度ログインして起動すると反映される。
  • 初回や未設定のときは内蔵のシンプルな画面になる。

セーフモード

URL に ?mode=safe を付けると、sys/components/ のコードとキャッシュ済みブートローダーを無視して、内蔵 UI で起動する。壊したコードの修復用。

デスクトップ環境のカスタマイズ

切り替えられるものは、すべて「フォルダに複数置いて、設定画面で選ぶ」形になっている。Linux のように、部品ごとに差し替えられる。

デスクトップ環境（sys/desktops/名前.json）

下の部品の選び方を、まとめて1つにしたもの。設定画面で選ぶと、中身が設定に書き込まれ、そのあとは個別にも変えられる。標準で classic（フローティング + タスクバー）、dock（丸い窓 + ガラスのドック + 動く壁紙）、tiling（タイル + ダーク + ネオンのカーソル）が入っている。

{ "windowManager": "tiling", "windowTheme": "dark", "shellTheme": "dark",
  "cursor": "neon", "wallpaper": "stars.html", "animation": null,
  "panel": "top", "keymap": "tiling", "iconset": null,
  "font": { "ui": "", "mono": "", "size": 14 } }

ウィンドウマネージャー（sys/wm/名前.js）

ウィンドウの置き方・並べ方・ボタンを決める JS。floating（標準）、tiling、fullscreen が入っている。読めないとき・セーフモードでは、内蔵の最小の WM になる。窓は、辺と角（8方向）をつかんで大きさを変えられる（resizable: false の WM では無効）。最大化中のボタンは「元に戻す」になる。

TrainOSWM.register({
  name: 'mine',
  buttons: ['min', 'max', 'close'],   // タイトルバーのボタン
  movable: true, resizable: true,
  open(w, ctx) { ctx.move(w, 40, 40, w.size.width, w.size.height); },  // 新しい窓を置く
  layout(wins, ctx) { },              // 窓が増減したとき・画面の大きさが変わったとき
  focus(w, wins, ctx) { },            // 窓が前面に出たとき
});
// w   = { id, app, el, bar, title, content, state, size }
// ctx = { area(), gap(), move(w, x, y, 幅, 高さ), raise(w), state(w, 'normal' | 'max' | 'min') }

ウィンドウテーマとシェルテーマ（CSS）

色や形は CSS 変数で決める。ウィンドウテーマ（sys/window_themes/）は窓、シェルテーマ（sys/shell_themes/）はデスクトップ・パネル・メニュー・アイコン。それぞれ別に選べる。

  • ウィンドウ: --win-bg --win-fg --win-border --win-radius --win-shadow --win-focus（前面の窓の輪郭）--title-bg --title-fg --title-pad --btn-gap。color-scheme も書ける。
  • シェル: --desk-bg --panel-bg --panel-fg --btn-bg --panel-radius（浮かぶパネルとメニューの角丸。端いっぱいのパネルには使われない）--panel-filter（例: blur(14px)）--panel-border（パネルとメニューのぼかしと縁。ガラスになる）--icon-fg --icon-size --icon-cell。
  • タイルの窓の間隔: --wm-gap（例: 8px）。
  • 部品を直接指定してもよい。id と class は変えない約束: #desktop #wp #icons .ico .win（.t タイトルバー、.btns、.c 中身、.front .min）#panel（.pk .pw）#menu。

アプリの中にも効く

ウィンドウテーマ、フォント、マウスカーソルは、アプリの中にも渡され、設定を変えると開いているアプリにもその場で反映される。アプリは var(--win-bg) var(--win-fg) var(--font-ui) var(--font-mono) var(--font-size) などを使える。自分のアプリで color-scheme を決め打ちしなければ、窓の色に合う。標準アプリは、この変数に従っている。セーフモードでは、何も渡されない。

パネル（sys/panels/名前.json）: ドックにもタスクバーにもなる

1つの仕組みで、画面の端いっぱいのタスクバーにも、浮かぶドックにもなる。標準で bottom（タスクバー）、top（細いバー）、dock（ドック）、left（自動で隠れる縦のドック）。

{ "position": "bottom",      // bottom / top / left / right
  "fill": true,              // true: 端いっぱい（窓はパネルの下に隠れない） false: 浮かぶ
  "size": 40,                // fill のときの高さ（幅）
  "iconSize": 28, "gap": 4, "radius": 16, "margin": 8, "opacity": 0.9,
  "labels": false, "autoHide": false,
  "items": [ {"type":"launcher"}, "explorer", "terminal",
             {"path":"/usr/documents","name":"書類","icon":"folder"},
             {"type":"windows"}, {"type":"spacer"},
             {"type":"save"}, {"type":"clock"}, {"type":"version"} ] }

項目は、アプリの id、path を持つオブジェクト、または type: launcher（アプリの一覧）、windows（開いている窓の一覧。押すと前面・最小化の切り替え）、save（Drive の保存）、clock、version、spacer（右寄せ用の空き）。

マウスカーソル（sys/cursors/名前.json）

種類ごとに SVG と、つかむ位置（x, y）を書く。種類は default pointer text move wait。SVG には width と height（128 以下）が必要。書かなかった種類は標準のカーソルのまま。アプリの中にも効く。

{ "default": { "svg": "<svg xmlns='http://www.w3.org/2000/svg' width='28' height='28'>...</svg>", "x": 3, "y": 3 } }

壁紙とアニメーション

  • sys/wallpapers/: 画像（png / jpg / gif / webp）、動く SVG（train.svg）、動く HTML（stars.html。Canvas などで描く。隔離された枠の中で動き、OS の機能には触れない）。設定では、#色 や /パス も指定できる。
  • sys/animations/名前.css: 窓が開く・閉じる・並び直すときの動き。.win.opening と .win.closing に animation を付け、--anim-close-ms（閉じるアニメーションの長さ。ミリ秒）と --snap-ms（並び直しの速さ）を書く。標準で fade zoom slide。

そのほか

  • sys/keymaps/名前.json: {"Alt+T":{"launch":"terminal"},"Alt+W":"closeWindow"}。アクションは launch（アプリ id と任意の openPath）、open（パス）、closeWindow launcher nextWindow prevWindow toMaster maximize minimize。Alt か Meta を含む組み合わせは、アプリの中でも効く。設定画面の「キー割り当て」で編集すると、sys/keymaps/custom.json に保存される（標準の割り当てには手を加えない）。
  • sys/iconsets/名前.json: {"cube":{"vb":"0 0 512 512","d":"..."}} のように、アイコン名ごとに SVG のパスを差し替える。
  • sys/fonts/: フォントファイル（woff2 / woff / ttf / otf）。設定画面で選ぶか、システムのフォント名を指定する。OS の画面とアプリの中の両方に効く（ファイルのフォントを、アプリの中に渡せるのは 2MB まで）。
  • sys/boot_loader/: 起動画面。sys/components/: 起動時に動く JS（ファイルごとにオンオフ）。sys/apps/: アプリ。

セーフモード（?mode=safe）では、これらのカスタマイズはすべて使われず、内蔵の見た目・最小の WM・内蔵のパネルで起動する。壊したときの修復用。

効果音（sys/sounds/）

設定画面の「効果音」で、テーマを選ぶ（既定はオフ）。音量もそこで変える。sys/sounds/名前.json がテーマで、キーがイベント名、値が音。default（やわらかい音）と retro（ピコピコ）が入っている。

{
  "launch": [[660, 0.06], [880, 0.09]],
  "close": "close.wav",
  "error": [{ "f": 200, "d": 0.2, "t": "square", "g": 0.4 }]
}
  • 音の並び（ファイル不要）: [周波数Hz, 秒] か { f, d, t（sine / square / triangle / sawtooth）, g（0〜1）, at（開始までの秒）}。at を省くと前の音のあとに続く。16 音まで、全体で 4 秒まで。
  • 音声ファイル: sys/sounds/ にある wav / mp3 / ogg / m4a / webm / flac（2MB まで）の名前を書く。
  • OS が鳴らすイベント: startup（起動）、launch（アプリを開く）、close（閉じる）、dialog（ダイアログが出る）、error（操作の失敗）、save（Drive に送った）。書いていないイベントは鳴らない。
  • 独自の名前も書ける。アプリは TrainOS.sound.play('名前')（権限は不要。1 秒に 8 回まで）、components は kernel.sound.play('名前') で鳴らす。_ で始めるキー（_comment など）や、形が不正なものは無視される。
  • ブラウザは、ページを操作する前の音を止めることがある。その場合、起動の音は鳴らず、最初の操作のあとから鳴る。
  • セーフモードでは鳴らさない。sys/sounds/ を編集すると、自動で読み直す。

起動時に開くアプリ（sys/startup/）

設定画面の「起動時に開くアプリ」で、アプリを選んで追加する。中身は sys/startup/名前.json（名前順に開く）。デスクトップが開いたあとに、順番に開く（権限の確認が出たら、答えるまで次を待つ）。

{ "app": "terminal" }
{ "app": "notepad", "openPath": "/usr/documents/memo.txt", "delay": 500 }
{ "open": "/usr/documents/memo.txt" }
[ { "app": "explorer" }, { "app": "terminal", "enabled": false } ]
  • app（アプリ id、任意の openPath）か、open（関連付けで開くパス）。配列で複数書ける。delay は開く前に待つ ms（10 秒まで）。"enabled": false で無効。
  • 設定画面のチェックを外すと、ファイルは残したまま、その名前が settings.json の disabledStartup に入って、開かなくなる。
  • 開きすぎて固まらないよう、1 回の起動で 10 個まで。失敗したものは飛ばして、続ける。
  • セーフモードでは、何も開かない。

標準ファイルの更新

起動時に、サイトの sys/defaults.json と手元の sys/installed.json を見比べ、バージョンが違うときだけ標準アプリ・起動画面を更新する。

  • 何バージョン離れていても、defaults.json には各ファイルの最新の版が書いてあるので、途中の版で変わったファイルもまとめて反映される。
  • 手を加えていないファイルは新しい版に置き換える。
  • 手を加えたファイルは上書きせず、名前.new として新しい版を横に置く。取り込むかどうかは自分で決める。
  • 自分で削除した標準ファイルは自動では戻さない。戻すときは設定の「標準ファイルを復元・更新」か、ターミナルの restore。
  • サイト側で削除・名前変更された標準ファイル（defaults.json の moved に書いてある）は、手を加えていなければ、古いほうを削除する（名前変更の新しいほうは、普通のコピーで入る。空になったフォルダも消す）。手を加えてあるものは、消さずに残す。更新の結果（削除したもの、残したもの）は、設定の「標準ファイルを復元・更新」とターミナルの restore に出る。

保存先

ローカルフォルダは Chrome / Edge（デスクトップ）のみ。選んだフォルダが TrainOS のルートになる。ブラウザを閉じるとフォルダの許可が切れることがあるので、index.html から起動して許可し直す。

Google Drive 版のセットアップ

  1. Firebase でプロジェクトを作り、Authentication で Google ログインを有効にする。配信元のドメインを承認済みドメインに追加する。
  2. 同じプロジェクトで Google Drive API を有効にする。
  3. firebase-config.js に Web アプリの設定値を入れる。
  4. 起動時に「Google でログイン」を押す。Drive のフルアクセス権限を求められる（確認前のアプリは警告が出る。自分用ならテストユーザーに自分を追加する）。

Drive の TrainOS/ フォルダがルートになる。書き込みはまとめて送られる（既定は10分ごと。設定画面で変えられる）。パネルの保存ボタンで今すぐ送れる。

  • タブを閉じても失わない: 送る前の編集は、ブラウザの IndexedDB にも保存される。次に開いたときに自動で戻り、保存ボタンに件数が出る。
  • 食い違い: 編集している間に Drive 側（別の端末など）でも同じファイルが変わっていたら、ダイアログで選ぶ。「両方残す」（このタブの内容を 名前.local-日時 として保存し、Drive の内容を残す。Esc も同じ）、「このタブの内容で上書き」、「Drive の内容を残す」。
  • ログインの期限切れ（約1時間）: ダイアログが出るので「Google でログイン」を押す。未送信の変更はそのまま残り、ログイン後に続きが送られる。「あとで」にすると、保存ボタンがオレンジになり、押すとログインできる。
  • オフライン: 編集は溜めたまま残り、つながると自動で送られる（失敗したら 30 秒、1 分、2 分…と間隔をあけて再送）。保存ボタンのオレンジ色と説明で状態が分かる。まだ開いていないファイルはオフラインでは開けない。オフラインでの起動は未対応（ログインに通信が要る）。
