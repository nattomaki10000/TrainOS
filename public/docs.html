TrainOS のトップへ

改造・独自アプリ docs

フォルダ構成

TrainOS/            選んだフォルダ（または Drive の TrainOS/）
├─ sys/
│  ├─ settings.json   設定（bootLoader, fileTypeHandlers ...）
│  ├─ boot_loader/    起動画面。複数置ける
│  ├─ themes/         テーマ（CSS）。複数置ける
│  ├─ wallpapers/     壁紙の画像。複数置ける
│  ├─ fonts/          フォントファイル
│  ├─ docks/          ドックの設定（JSON）。複数置ける
│  ├─ keymaps/        キー割り当て（JSON）。複数置ける
│  ├─ iconsets/       アイコンの差し替え（JSON）。複数置ける
│  ├─ components/     OS の挙動を差し替える JS。ファイルごとにオンオフ
│  └─ apps/           アプリ。置くだけで使える
└─ usr/               desktop/ documents/ など

アプリを作る

単体HTML型: sys/apps/hello.html を置くだけ。

<pre id="out">読み込み中…</pre>
<script>
TrainOS.fs.readText('/usr/documents/memo.txt')
  .then(t => out.textContent = t)
  .catch(e => out.textContent = e.message);
</script>

フォルダ型（推奨）: sys/apps/mytool/ に index.html と app.json など。CSS・JS・画像を分けられる。

{
  "id": "mytool", "name": "My Tool",
  "entry": "index.html",
  "extensions": ["txt"],
  "permissions": ["fs.read", "fs.write"]
}

SDK（アプリ内の window.TrainOS）:

TrainOS.fs.readFile(p) / readText(p) / writeFile(p, data)
TrainOS.fs.list(p) / tree(p) / mkdir(p) / remove(p)
TrainOS.app.setTitle(t) / close() / openFile(p)
TrainOS.app.onOpen(fn)   // 他から開かれたとき fn(path)
TrainOS.fs.move(from, to)
TrainOS.sys.getSettings() / setSettings(patch) / flush()   // system.settings が必要
TrainOS.icon(name)       // Font Awesome の SVG 文字列
  • 権限: fs.read fs.write app.launch（openFile 用）、system.settings（設定の読み書き）。app.json で指定すると既定値を置き換える。
  • 相対パスの script / link / img はアプリフォルダ内だけ解決される。実行時の fetch や import() では同フォルダを読めないので TrainOS.fs を使う。
  • alert / prompt / confirm は使えない。

起動画面（ブートローダー）

sys/boot_loader/名前.js を置く。example.js（プログレスバー）と redver.js（赤いスピナー）が入っている。

TrainOSBoot.register({
  name: 'mine',
  start(el) { el.textContent = 'booting…'; },   // el = 起動画面の要素
  progress({ value, label }) { /* 0-100 と表示文字 */ },
  done() {}                                      // 省略可
});
  • 切り替え: settings.json の bootLoader を名前にする。設定画面やターミナルからは TrainOSBoot.use(kernel, '名前')。
  • ログイン前は Drive を読めないため、選択中のローダーはブラウザにキャッシュされ、次回起動時に使われる。ファイルを編集したら、一度ログインして起動すると反映される。
  • 初回や未設定のときは内蔵のシンプルな画面になる。

セーフモード

URL に ?mode=safe を付けると、sys/components/ のコードとキャッシュ済みブートローダーを無視して、内蔵 UI で起動する。壊したコードの修復用。

カスタマイズの置き場所

切り替えられるものは、フォルダに複数置いて、設定画面から選べる。

  • sys/boot_loader/ 起動画面。
  • sys/themes/名前.css テーマ。色は CSS 変数で決める: --desk-bg --bar-bg --bar-fg --btn-bg --win-bg --win-fg --title-bg --title-fg --icon-fg、さらに --win-radius --win-border --win-shadow --title-pad --icon-size --icon-cell --anim（窓が開くときの秒数）--dock-bg --dock-fg --dock-radius。color-scheme も書ける。
  • sys/wallpapers/ 壁紙の画像（png / jpg / gif / webp / svg）。
  • sys/components/名前.js 起動時に実行される JS（kernel が渡される）。設定画面でファイルごとにオンオフできる（次回の起動から）。セーフモードでは実行されない。
  • sys/docks/名前.json ドック。{"position":"bottom","iconSize":44,"gap":8,"radius":16,"opacity":0.9,"labels":false,"autoHide":false,"items":["explorer","terminal",{"path":"/usr/documents","name":"書類","icon":"folder"}]}。位置は bottom / top / left / right。項目はアプリの id か、path を持つオブジェクト。起動中のアプリには点が付き、押すと前面に出る。
  • sys/keymaps/名前.json キー割り当て。{"Alt+T":{"launch":"terminal"},"Alt+W":"closeWindow","Alt+Space":"launcher"}。アクションは launch（アプリの id と任意の openPath）、open（パス）、closeWindow、launcher。Alt か Meta を含む組み合わせは、アプリの中でも効く。
  • sys/iconsets/名前.json アイコンセット。{"cube":{"vb":"0 0 512 512","d":"..."}} のように、アイコン名ごとに SVG のパスを差し替える（example.json 参照）。
  • sys/fonts/ フォントファイル（woff2 / woff / ttf / otf）。設定画面で選ぶか、システムにあるフォント名を指定する。いまは OS の画面（バー、ウィンドウの枠、アイコン）に効く。アプリの中は v0.5.0 の予定。
  • sys/apps/ アプリ。

テーマの CSS では、変数だけでなく部品を直接指定してもよい。部品の id と class は変えない約束にしている: #desktop #icons .ico .win .t（タイトルバー）.c（中身）#bar #menu #dock .dk。セーフモードでは、テーマ・フォント・ドック・キー割り当て・アイコンセットは使われない。

今後の予定: タスクバーのカスタマイズ、効果音、起動時に開くアプリ。

標準ファイルの更新

起動時に、サイトの sys/defaults.json と手元の sys/installed.json を見比べ、バージョンが違うときだけ標準アプリ・起動画面を更新する。

  • 何バージョン離れていても、defaults.json には各ファイルの最新の版が書いてあるので、途中の版で変わったファイルもまとめて反映される。
  • 手を加えていないファイルは新しい版に置き換える。
  • 手を加えたファイルは上書きせず、名前.new として新しい版を横に置く。取り込むかどうかは自分で決める。
  • 自分で削除した標準ファイルは自動では戻さない。戻すときは設定の「標準ファイルを復元・更新」か、ターミナルの restore。

保存先

ローカルフォルダは Chrome / Edge（デスクトップ）のみ。選んだフォルダが TrainOS のルートになる。ブラウザを閉じるとフォルダの許可が切れることがあるので、index.html から起動して許可し直す。

Google Drive 版のセットアップ

  1. Firebase でプロジェクトを作り、Authentication で Google ログインを有効にする。配信元のドメインを承認済みドメインに追加する。
  2. 同じプロジェクトで Google Drive API を有効にする。
  3. firebase-config.js に Web アプリの設定値を入れる。
  4. 起動時に「Google でログイン」を押す。Drive のフルアクセス権限を求められる（確認前のアプリは警告が出る。自分用ならテストユーザーに自分を追加する）。

Drive の TrainOS/ フォルダがルートになる。書き込みはまとめて送られるので、タスクバーの保存ボタンで今すぐ送れる。
