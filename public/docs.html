TrainOS のトップへ

改造・独自アプリ docs

フォルダ構成

TrainOS/            選んだフォルダ（または Drive の TrainOS/）
├─ sys/
│  ├─ settings.json   設定
│  ├─ desktops/       デスクトップ環境（全部の設定のまとめ。JSON）
│  ├─ wm/             ウィンドウマネージャー（JS）
│  ├─ window_themes/  ウィンドウテーマ（CSS）
│  ├─ shell_themes/   シェルテーマ（CSS）
│  ├─ panels/         パネル = ドック・タスクバー（JSON）
│  ├─ cursors/        マウスカーソル（JSON）
│  ├─ animations/     アニメーション（CSS）
│  ├─ wallpapers/     壁紙（画像、動く SVG、動く HTML）
│  ├─ fonts/          フォント
│  ├─ keymaps/        キー割り当て（JSON）
│  ├─ iconsets/       アイコンの差し替え（JSON）
│  ├─ boot_loader/    起動画面（JS）
│  ├─ components/     起動時に動く JS。ファイルごとにオンオフ
│  └─ apps/           アプリ。置くだけで使える
└─ usr/               desktop/ documents/ など

アプリを作る

単体HTML型: sys/apps/hello.html を置くだけ。

<pre id="out">読み込み中…</pre>
<script>
TrainOS.fs.readText('/usr/documents/memo.txt')
  .then(t => out.textContent = t)
  .catch(e => out.textContent = e.message);
</script>

フォルダ型（推奨）: sys/apps/mytool/ に index.html と app.json など。CSS・JS・画像を分けられる。

{
  "id": "mytool", "name": "My Tool",
  "entry": "index.html",
  "extensions": ["txt"],
  "permissions": ["fs.read", "fs.write"]
}

SDK（アプリ内の window.TrainOS）:

TrainOS.fs.readFile(p) / readText(p) / writeFile(p, data)
TrainOS.fs.list(p) / tree(p) / mkdir(p) / remove(p)
TrainOS.app.setTitle(t) / close() / openFile(p)
TrainOS.app.onOpen(fn)   // 他から開かれたとき fn(path)
TrainOS.fs.move(from, to)
TrainOS.sys.getSettings() / setSettings(patch) / flush()   // system.settings が必要
TrainOS.icon(name)       // Font Awesome の SVG 文字列
  • 権限: fs.read fs.write app.launch（openFile 用）、system.settings（設定の読み書き）。app.json で指定すると既定値を置き換える。
  • 相対パスの script / link / img はアプリフォルダ内だけ解決される。実行時の fetch や import() では同フォルダを読めないので TrainOS.fs を使う。
  • alert / prompt / confirm は使えない。

起動画面（ブートローダー）

sys/boot_loader/名前.js を置く。example.js（プログレスバー）と redver.js（赤いスピナー）が入っている。

TrainOSBoot.register({
  name: 'mine',
  start(el) { el.textContent = 'booting…'; },   // el = 起動画面の要素
  progress({ value, label }) { /* 0-100 と表示文字 */ },
  done() {}                                      // 省略可
});
  • 切り替え: settings.json の bootLoader を名前にする。設定画面やターミナルからは TrainOSBoot.use(kernel, '名前')。
  • ログイン前は Drive を読めないため、選択中のローダーはブラウザにキャッシュされ、次回起動時に使われる。ファイルを編集したら、一度ログインして起動すると反映される。
  • 初回や未設定のときは内蔵のシンプルな画面になる。

セーフモード

URL に ?mode=safe を付けると、sys/components/ のコードとキャッシュ済みブートローダーを無視して、内蔵 UI で起動する。壊したコードの修復用。

デスクトップ環境のカスタマイズ

切り替えられるものは、すべて「フォルダに複数置いて、設定画面で選ぶ」形になっている。Linux のように、部品ごとに差し替えられる。

デスクトップ環境（sys/desktops/名前.json）

下の部品の選び方を、まとめて1つにしたもの。設定画面で選ぶと、中身が設定に書き込まれ、そのあとは個別にも変えられる。標準で classic（フローティング + タスクバー）、dock（丸い窓 + ガラスのドック + 動く壁紙）、tiling（タイル + ダーク + ネオンのカーソル）が入っている。

{ "windowManager": "tiling", "windowTheme": "dark", "shellTheme": "dark",
  "cursor": "neon", "wallpaper": "stars.html", "animation": null,
  "panel": "top", "keymap": "tiling", "iconset": null,
  "font": { "ui": "", "mono": "", "size": 14 } }

ウィンドウマネージャー（sys/wm/名前.js）

ウィンドウの置き方・並べ方・ボタンを決める JS。floating（標準）、tiling、fullscreen が入っている。読めないとき・セーフモードでは、内蔵の最小の WM になる。

TrainOSWM.register({
  name: 'mine',
  buttons: ['min', 'max', 'close'],   // タイトルバーのボタン
  movable: true, resizable: true,
  open(w, ctx) { ctx.move(w, 40, 40, w.size.width, w.size.height); },  // 新しい窓を置く
  layout(wins, ctx) { },              // 窓が増減したとき・画面の大きさが変わったとき
  focus(w, wins, ctx) { },            // 窓が前面に出たとき
});
// w   = { id, app, el, bar, title, content, state, size }
// ctx = { area(), gap(), move(w, x, y, 幅, 高さ), raise(w), state(w, 'normal' | 'max' | 'min') }

ウィンドウテーマとシェルテーマ（CSS）

色や形は CSS 変数で決める。ウィンドウテーマ（sys/window_themes/）は窓、シェルテーマ（sys/shell_themes/）はデスクトップ・パネル・メニュー・アイコン。それぞれ別に選べる。

  • ウィンドウ: --win-bg --win-fg --win-border --win-radius --win-shadow --win-focus（前面の窓の輪郭）--title-bg --title-fg --title-pad --btn-gap。color-scheme も書ける。
  • シェル: --desk-bg --panel-bg --panel-fg --btn-bg --panel-radius --icon-fg --icon-size --icon-cell。
  • タイルの窓の間隔: --wm-gap（例: 8px）。
  • 部品を直接指定してもよい。id と class は変えない約束: #desktop #wp #icons .ico .win（.t タイトルバー、.btns、.c 中身、.front .min）#panel（.pk .pw）#menu。

パネル（sys/panels/名前.json）: ドックにもタスクバーにもなる

1つの仕組みで、画面の端いっぱいのタスクバーにも、浮かぶドックにもなる。標準で bottom（タスクバー）、top（細いバー）、dock（ドック）、left（自動で隠れる縦のドック）。

{ "position": "bottom",      // bottom / top / left / right
  "fill": true,              // true: 端いっぱい（窓はパネルの下に隠れない） false: 浮かぶ
  "size": 40,                // fill のときの高さ（幅）
  "iconSize": 28, "gap": 4, "radius": 16, "margin": 8, "opacity": 0.9,
  "labels": false, "autoHide": false,
  "items": [ {"type":"launcher"}, "explorer", "terminal",
             {"path":"/usr/documents","name":"書類","icon":"folder"},
             {"type":"windows"}, {"type":"spacer"},
             {"type":"save"}, {"type":"clock"}, {"type":"version"} ] }

項目は、アプリの id、path を持つオブジェクト、または type: launcher（アプリの一覧）、windows（開いている窓の一覧。押すと前面・最小化の切り替え）、save（Drive の保存）、clock、version、spacer（右寄せ用の空き）。

マウスカーソル（sys/cursors/名前.json）

種類ごとに SVG と、つかむ位置（x, y）を書く。種類は default pointer text move wait。SVG には width と height（128 以下）が必要。書かなかった種類は標準のカーソルのまま。アプリの中にも効く。

{ "default": { "svg": "<svg xmlns='http://www.w3.org/2000/svg' width='28' height='28'>...</svg>", "x": 3, "y": 3 } }

壁紙とアニメーション

  • sys/wallpapers/: 画像（png / jpg / gif / webp）、動く SVG（train.svg）、動く HTML（stars.html。Canvas などで描く。隔離された枠の中で動き、OS の機能には触れない）。設定では、#色 や /パス も指定できる。
  • sys/animations/名前.css: 窓が開く・閉じる・並び直すときの動き。.win.opening と .win.closing に animation を付け、--anim-close-ms（閉じるアニメーションの長さ。ミリ秒）と --snap-ms（並び直しの速さ）を書く。標準で fade zoom slide。

そのほか

  • sys/keymaps/名前.json: {"Alt+T":{"launch":"terminal"},"Alt+W":"closeWindow"}。アクションは launch（アプリ id と任意の openPath）、open（パス）、closeWindow launcher nextWindow prevWindow toMaster maximize minimize。Alt か Meta を含む組み合わせは、アプリの中でも効く。
  • sys/iconsets/名前.json: {"cube":{"vb":"0 0 512 512","d":"..."}} のように、アイコン名ごとに SVG のパスを差し替える。
  • sys/fonts/: フォントファイル（woff2 / woff / ttf / otf）。設定画面で選ぶか、システムのフォント名を指定する。いまは OS の画面に効く（アプリの中は v0.5.0 の予定）。
  • sys/boot_loader/: 起動画面。sys/components/: 起動時に動く JS（ファイルごとにオンオフ）。sys/apps/: アプリ。

セーフモード（?mode=safe）では、これらのカスタマイズはすべて使われず、内蔵の見た目・最小の WM・内蔵のパネルで起動する。壊したときの修復用。

今後の予定: 効果音、起動時に開くアプリ。

標準ファイルの更新

起動時に、サイトの sys/defaults.json と手元の sys/installed.json を見比べ、バージョンが違うときだけ標準アプリ・起動画面を更新する。

  • 何バージョン離れていても、defaults.json には各ファイルの最新の版が書いてあるので、途中の版で変わったファイルもまとめて反映される。
  • 手を加えていないファイルは新しい版に置き換える。
  • 手を加えたファイルは上書きせず、名前.new として新しい版を横に置く。取り込むかどうかは自分で決める。
  • 自分で削除した標準ファイルは自動では戻さない。戻すときは設定の「標準ファイルを復元・更新」か、ターミナルの restore。

保存先

ローカルフォルダは Chrome / Edge（デスクトップ）のみ。選んだフォルダが TrainOS のルートになる。ブラウザを閉じるとフォルダの許可が切れることがあるので、index.html から起動して許可し直す。

Google Drive 版のセットアップ

  1. Firebase でプロジェクトを作り、Authentication で Google ログインを有効にする。配信元のドメインを承認済みドメインに追加する。
  2. 同じプロジェクトで Google Drive API を有効にする。
  3. firebase-config.js に Web アプリの設定値を入れる。
  4. 起動時に「Google でログイン」を押す。Drive のフルアクセス権限を求められる（確認前のアプリは警告が出る。自分用ならテストユーザーに自分を追加する）。

Drive の TrainOS/ フォルダがルートになる。書き込みはまとめて送られるので、タスクバーの保存ボタンで今すぐ送れる。
